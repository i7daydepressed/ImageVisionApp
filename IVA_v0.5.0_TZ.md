## 2. Согласованный интерфейс

Отдельная основная вкладка с иконкой лица, доступным названием «Лица» и собственной рабочей областью. Вся работа ЛР5 находится внутри неё. Вкладка открывается и без документа в остальных вкладках. Детали компоновки уточняются в пакетах интерфейса.

- **«Лица → База лиц».** Слева список профилей с именем, аватаром и числом образцов. Справа карточка выбранного профиля. Во время импорта показываются фото и рамки обнаруженных лиц. При одном лице область выбирается автоматически. При нескольких пользователь указывает нужную рамку. Действия — «Создать профиль», «Добавить фото…», «Сохранить», «Переименовать» и «Удалить профиль». Результат проверки виден у каждого выбранного файла. Если импорт прерван или проверка завершилась ошибкой, сохраненные профили остаются доступны.
- **«Лица → Распознавание».** Камера и видеофайл доступны одновременно как варианты выбора. У камеры есть запуск, остановка и предпросмотр с рамками. Каждое обнаруженное лицо получает свою рамку. Если совпадение принято, над рамкой показывается имя. Другие состояния — «Неизвестное лицо», «Лицо не найдено», «База пуста» и причина недоступности камеры. Видеофайл открывается здесь же и получает свои команды воспроизведения, паузы и перемотки.

### Ядро 068

`FacePhotoDecoder.Decode()` применяет ориентацию фото и выдает плотный BGR8. Для прозрачного фото подложка черная. Готовый кадр передается через `FaceImage.FromBgr8()`, который копирует пиксели. `FacePipelineService.Detect()` возвращает упорядоченные слева направо рамки и пять ориентиров в исходных координатах. Результат хранит тот же снимок. `ExtractEmbedding()` получает этот результат и индекс лица, выравнивает область до 112×112 и возвращает нормированный вектор из 128 чисел, выровненный фрагмент и версию конвейера. [FacePhotoDecoder.cs](Services/FacePhotoDecoder.cs) · [FaceImage.cs](Models/FaceImage.cs) · [FacePipelineService.cs](Services/FacePipelineService.cs)

При создании сессии пути к ONNX передаются явно. OpenCV получает байты, проверенные по размеру и SHA-256. Настройка файлов для 070 описана ниже.

### Хранилище 069

`FaceProfileStore` получает абсолютный корень рабочей копии и читает `face-data/profiles.json`. При первом чтении сервис возвращает пустой список. Папка создается при первой записи. `Create()` и `AddSamples()` копируют нормированные 128-мерные векторы текущей версии конвейера. Переименование и удаление выполняются по стабильному ID. JSON версии 1 хранит ID, имя и образцы профиля. [FaceProfileStore.cs](Services/FaceProfileStore.cs) · [FaceProfile.cs](Models/FaceProfile.cs)

При изменении сервис проверяет пути, берет общую блокировку `profiles.lock` и перечитывает актуальную базу. Подтверждение возвращается после записи временного файла, сброса на диск и замены базы в той же папке. Поврежденный или несовместимый файл остается доступен для отдельного восстановления. Папка исключена из Git. Блокировка проверяется для локальных процессов, синхронизация между устройствами в этот контракт не входит.

### Экран базы 070

Кнопка с иконкой лица открывает «Базу лиц» даже без общего медиадокумента. У базы свой диалог импорта. Одиночная рамка выбирается автоматически, на групповом фото пользователь выбирает рамку или ее номер. Список импорта показывает результат по каждому фото. После нажатия «Сохранить» выбранные образцы записываются одной операцией. При уходе с незаписанными правками окно запрашивает подтверждение сброса. Исходные фото и предпросмотры в базу не копируются. Выход из вкладки возвращает прежний медиадокумент.

Рядом с именем профиля отображается геометрический аватар. HMAC-SHA-256 от ID профиля и его первого сохраненного вектора задает цвет и рисунок 7×7. Ключ хранится в локальных данных приложения, схема базы остается прежней. При том же ключе рисунок сохраняется при переименовании, добавлении образцов и перезапуске. Если ключ недоступен, показывается нейтральный значок. [FaceProfileAvatars.cs](Services/FaceProfileAvatars.cs) · [FaceProfileAvatar.cs](Views/FaceProfileAvatar.cs)

В реализации 070 в карточке сохраненного профиля можно выбрать любой его образец. Справа выводятся все 128 компонент уже сохраненного вектора с нумерацией в исходном порядке. Просмотр использует текущую базу и доступен для профилей, созданных до появления этой панели. [FaceDatabaseView.cs](Views/FaceDatabaseView.cs)

Для запуска из checkout положите оба ONNX в `face-models/` в корне проекта. Приложение ищет корень вверх от каталога сборки по `.git` и `ImageVisionApp.csproj`. Если сборка находится вне checkout, задайте абсолютный путь к checkout через `IMAGEVISIONAPP_CHECKOUT_ROOT`. Папка `face-models/` исключена из Git. Для импорта используйте указанные файлы OpenCV Zoo. Загрузка из сети выполняется отдельно от приложения. [FaceWorkspacePaths.cs](Services/FaceWorkspacePaths.cs)

### Карточка профиля 070.1

В 070.1 в карточке сохраненного профиля появились вкладки «Образцы» и «Сравнение образцов». В шапке виден аватар профиля. Выбор образца общий для двух вкладок. В сравнении опорный образец выбирается в списке «Сравнить с», рядом видна подсказка о косинусном сходстве.

Остальные образцы этого профиля упорядочены по полному косинусному сходству по убыванию. При равенстве сохраняется порядок добавления. Справа в каждой строке показана оценка с двумя знаками. При одном образце карточка предлагает добавить еще один снимок. [FaceDatabaseView.Comparison.cs](Views/FaceDatabaseView.Comparison.cs)

### Таблица сходства образцов 070.2

В 070.2 вкладка сравнения показывает таблицу всех пар одного профиля. Номера образцов идут сверху и слева в порядке добавления. На пересечении отображается косинусное сходство с двумя знаками, на диагонали ставится прочерк. При одном образце окно предлагает добавить еще один снимок.

Для больших профилей таблица прокручивается по двум осям с заголовками видимых строк и столбцов. Приложение вычисляет оценки только для видимых ячеек. Стрелки прокручивают таблицу, когда на ней установлен фокус. [FaceDatabaseView.Comparison.cs](Views/FaceDatabaseView.Comparison.cs)

### Распознавание из видео 071

В «Лица → Распознавание» видео MP4 или MKV открывается своим диалогом. У вкладки свой экземпляр `VideoPlaybackSession`, ползунок и кнопка воспроизведения. При фокусе в предпросмотре пробел управляет паузой, стрелки перематывают на одну секунду. При уходе вкладка сохраняет файл и позицию, а при возврате показывает кадр на паузе. [FaceRecognitionView.cs](Views/FaceRecognitionView.cs)

`VideoPlaybackFrames.Capture()` копирует пиксели текущей ревизии. `FaceRecognitionService` обнаруживает лица и считает признаки для каждой рамки, затем выбирает лучший косинус по образцам каждого профиля. Уникальное лучшее совпадение принимается от 0,363. При точной ничьей между профилями показывается «Неизвестное лицо». Для порога проведена учебная проверка на каталоге из двух профилей. [FaceRecognitionService.cs](Services/FaceRecognitionService.cs) · [Порог OpenCV для LFW](https://docs.opencv.org/4.13.0/d0/dd4/tutorial_dnn_face.html)

`FaceRecognitionPreview` показывает копию кадра вместе с его рамками и подписями. Во время воспроизведения каждый свободный проход берет свежий кадр. На паузе и при перемотке кадр читается в выбранной точке через `VideoFirstFrameReader`. Поздний результат отмененного запроса отбрасывается. Вкладка различает пустую базу, кадр без лица и ошибку загрузки. [FaceRecognitionPreview.cs](Views/FaceRecognitionPreview.cs) · [VideoFirstFrameReader.cs](Services/VideoFirstFrameReader.cs)

## 5. Проверки по ходу работы

- До внедрения подтвердить, что приложение может получить непустые кадры камеры на целевом Mac и освобождать устройство. Определение камеры системной утилитой подтверждает наличие устройства. Разрешение приложения и захват кадров проверяются отдельно.
- Для живого режима замерить частоту поступления и обработки кадров и задержку результата на контрольном запуске. При отставании ограничивать ожидание, чтобы старые кадры не накапливались. Смену источника, остановку и выход с экрана проверять при активном расчёте.
- Для проверки профилей использовать разные примеры добавления и распознавания. Сохранить случаи правильного совпадения, отказа для неизвестного человека и ограничений при сложном ракурсе или освещении.
- Для отчёта сохранять версию сборки, источник, условие прогона, наблюдение и нужный кадр или снимок. Сборка, автоматический прогон, проверка в окне и приёмка пользователя указываются отдельно.
- Для файлового сценария проверить переключение между «Лицами» и редактором с двумя разными файлами, в том числе пробел и стрелки в каждом режиме. Редактор сохраняет свой документ, очередь и позицию, а «Лица» — свой файловый вход. Перед завершением ЛР5 повторить работу существующих вкладок и один сценарий экспорта. Точные шаги по пакетам приведены в [плане](IVA_v0.5.0_package_plan.md).
